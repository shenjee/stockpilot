## 2. 目的与边界

本文档将 PRD 中的三栏工作台固化为可实现、可测试和可验收的 UI 规格，作为前端布局、图表封装和产品验收的共同基线。

本文档只定义工作台的结构、布局状态、图表联动边界、信息层级和状态保持规则。具体颜色、字体、线宽和图标等视觉 Token 可在不改变本文档交互与布局约束的前提下迭代。

## 3. 工作台总体结构

实盘与历史回放共用同一个工作台，不建设两套图表页面。模式切换只替换数据、时钟和图表下方的回放操作面板，不改变三栏主体结构。

```text
顶部工具栏
├── 代码输入
├── 股票名称
└── 实盘 / 回放双态按钮

主工作区
├── 5 分钟区：价格图 / VOL / MACD
├── 中间副图：分时（1 分钟价格与 VWAP / 1 分钟 VOL / 1 分钟 MACD）或 30 分钟（价格图 / VOL / MACD）
└── 固定行情栏：日 K / 行情数据

回放操作面板
└── 仅回放模式显示，位于三栏工作区下方

底部
└── T+0 成交折叠栏
```

## 4. 主工作区网格

### 4.1 列布局

主工作区使用三列网格：

```text
┌── 5 分钟区 ──┬── 分时或 30 分钟 ──┬── 行情栏 280px ──┐
│                 │                    │                    │
│ 价格图          │ 价格图             │ 日 K               │
│                 │                    │ 行情数据           │
├── VOL ─────────┤ VOL ───────────────┤ 最新价/涨跌幅      │
├── MACD ────────┤ MACD ──────────────┤ 开高低/昨收       │
│                 │                    │ 量额/量比/换手/委比│
│                 │                    │      数据截止 …   │
└─────────────────┴────────────────────┴────────────────────┘
```

最右行情栏宽度约为 `280px`，在两种布局中保持不变，不参与 5 分钟区和中间副图的比例分配。如因系统缩放或窗口边框产生少量误差，应优先保证字段完整可读，不得隐藏行情栏。

最右行情栏跨越图表区的三行，但不参与价格图、VOL 和 MACD 的水平分界对齐；它的日 K 与「行情数据」区块使用独立内部布局。「数据截止」不属于行情字段网格，仅作为该区块下方的元信息行。

### 4.2 行布局

5 分钟区和中间副图共用相同的三行网格：

1. 价格图；
2. VOL；
3. MACD。

两个区域的行起点、行终点和行间距必须一致，不得由左右子组件独立计算高度。价格图使用 `minmax(300px, 1fr)` 占用剩余垂直空间；VOL 和 MACD 的开发基准高度均为 `88px`。真机视觉微调可在 `80–96px` 内进行，但必须由同一设计 Token 同时作用于左右两组图表。

窗口竖向空间改变时，优先调整价格图高度，VOL 和 MACD 应保持可读且两侧等高。

### 4.3 图表绘图区与右侧 Y 轴

5 分钟区和分时区分别是一个自上而下排列的图表列。每列内的价格图、VOL 和 MACD 必须满足以下几何约束：

- 三个图表容器的左边界和右边界完全对齐；
- 扣除右侧 Y 轴后的实际绘图区左边界和右边界完全一致；
- 三个图表使用相同的时间轴宽度，同一时间点在三行中的水平坐标必须一一对应；
- 图表标题、工具按钮或指标图例不得单独挤压某一行的绘图区。

六张图表——5 分钟价格图、5 分钟 VOL、5 分钟 MACD、1 分钟价格图、1 分钟 VOL、1 分钟 MACD——共用同一个右侧 Y 轴宽度 Token：

```text
chartRightYAxisWidth = 72px
```

该 Token 由产品侧定义；六张图的实现必须引用同一 Token，不得根据某一张图当前数值的字符数量动态伸缩，也不得由各图表实例独立计算或单独加宽。开发基准为 `72px`，并在当前图表字体下保留标签所需的左右内边距。

`9999.99`、`-9999.99`、`1234.57万` 是**字符容量样例**，用于标定标签区最坏宽度，不是普通 Y 轴刻度的输出格式。`chartRightYAxisWidth` 至少须完整容纳以下最坏样例：

- 价格 / 当前价标签：`9999.99`
- 带负号的 MACD 标签：`-9999.99`
- VOL 紧凑缩写：`1234.57万`

五位及以上整数必须完整显示，不截断、不换行、不使用科学计数法。若实际字符串超出当前预算，或后续字体 Token 变化导致空间不足，只能统一提高六张图共用的 `chartRightYAxisWidth`，不能在运行时只加宽单张图。

#### 普通刻度的生成与标签格式化

除第 6.2 节定义的分时价格图固定中轴坐标外，普通 Y 轴刻度不是从行情数据中直接抽取某个原始价格作为刻度。图表坐标轴应先根据当前可见数据范围以及参与自动缩放的可见系列计算纵轴范围，再自动选择整齐、可读的刻度间隔并生成刻度点。分时价格图的范围与刻度优先遵守第 6.2 节，不得被本节的普通自动缩放规则覆盖。

刻度生成与标签格式化是两个独立阶段，完整处理过程如下：

1. 坐标轴算法根据可见数据计算大致的最小值和最大值；
2. 坐标轴算法选择合适的整齐间隔；
3. 坐标轴在整齐间隔对应的点上生成普通刻度；
4. 标签格式化函数只负责将已经生成的刻度点转换为最终显示文字。

轴范围与间隔由统一的坐标轴算法负责，业务代码不得通过遍历行情原始值来拼装普通刻度。同时，当价格/MACD 轴的可见范围绝对值达到或超过 `100` 时，必须把刻度生成约束切换为整数锚定：

- `abs(tick) >= 100` 时，刻度点本身必须是整数；
- 该区间相邻刻度间隔不小于 `1`；
- 不得出现两个不同刻度点格式化后显示相同标签；
- 标签文字对应的数值必须与网格线实际坐标值一致（禁止 `100.5` 刻度显示为 `101`）。

在绝对值小于 `100` 的区间，典型间隔仍可为 `0.5 / 1 / 2 / 5 / 10` 及其十进制倍数。实现上通过 Lightweight Charts 系列 `priceFormat.minMove`（`<100` 用 `0.01`，范围触及 `>=100` 时用 `1`）约束刻度生成；用户平移或缩放导致可见价格范围跨过该阈值时，必须在范围同步与布局完成后重新计算 `minMove`。`tickmarksFormatter` 只负责显示文字，不替代上述生成约束。

| 对象 | 数值来源 | 格式规则的作用 |
| --- | --- | --- |
| 普通 Y 轴刻度 | 坐标轴算法根据可见范围生成的整齐间隔点 | 决定刻度点最终显示为两位小数还是整数 |
| 当前价格标签 | 当前价格系列的真实最新数据值 | 始终显示两位小数 |
| 价格、MACD 十字光标标签 | 十字光标所在时间对应系列的真实数据值 | 始终显示两位小数 |
| VOL 普通刻度与十字光标标签 | 坐标轴刻度点或十字光标所在时间对应的真实成交量 | 使用成交量紧凑缩写格式 |

右侧 Y 轴**普通刻度**（不含十字光标、不含当前价标签）按以下顺序格式化：

1. 先将原始数值按两位小数四舍五入；
2. 再取舍入后数值的绝对值，判断是否达到 `100`；
3. 若 `abs(rounded) < 100`，输出两位小数，例如 `12.34`、`99.99`、`99.00`、`-5.20`；
4. 若 `abs(rounded) >= 100`，将两位小数结果再次按整数四舍五入并保留原符号，输出不带小数部分的整数，例如 `100.40 → 100`、`100.60 → 101`、`-100.60 → -101`。

统一格式化函数的边界测试应满足：`99.996 → 100`、`99.994 → 99.99`、`-99.995 → -100`、`100.60 → 101`、`-100.60 → -101`。这些测试值用于固定格式化函数的边界行为，不表示自动坐标轴通常会生成这些数值作为普通刻度。

VOL 普通刻度继续使用现有成交量紧凑缩写格式，例如 `25万`、`200万`、`1234.57万`，不应用上述小数位规则，但仍使用相同的 `chartRightYAxisWidth`。

价格图主系列的当前价格标签必须显示，且始终保留两位小数，例如 `949.91`，不受普通 Y 轴刻度规则影响。

十字光标数值标签：

- 价格图：始终保留两位小数，例如 `949.91`；
- MACD：始终保留两位小数；
- VOL：继续使用成交量紧凑缩写格式。

#### Lightweight Charts 版本约束与完成门槛

当前应用依赖并锁定 `lightweight-charts 5.2.0`（见 ADR 0009 / Issue #124）。5.x 自定义价格格式将精确标签与普通刻度职责分离：

- `formatter` / `localization.priceFormatter`：用于当前价格和价格/MACD 十字光标，始终保留两位小数；
- `tickmarksFormatter` / `localization.tickmarksPriceFormatter`：只用于普通价格/MACD 刻度，执行 `< 100` 显示两位小数、`>= 100` 显示整数的规则；
- VOL 继续使用独立的成交量紧凑缩写格式。

因此，同一数值可以在普通刻度显示为 `100`，同时在当前价或十字光标显示为 `100.00`。Issue #123 的关闭门槛是真实 Lightweight Charts 渲染路径同时满足上述两套规则，而不是仅在纯函数单测中通过。

固定 Y 轴宽度既用于防止数值位数变化引起图表横向抖动，也用于保证同一列三张图的实际绘图区和时间坐标持续对齐。布局比例切换、窗口缩放、切换股票、实盘刷新和历史回放均不得破坏上述约束。

## 5. 两种布局状态

图表工作区内始终提供布局切换入口，不放在顶部工具栏。布局为同一工作台的显示状态，不是路由或独立页面。不再区分 64/36 与 50/50 两种比例；显示副图时固定各占图表剩余宽度的 50%。

| 布局 | 5 分钟区 | 中间副图 | 最右行情栏 |
| --- | ---: | ---: | ---: |
| 显示副图（默认） | 剩余图表空间的 50% | 剩余图表空间的 50%；内容为分时或 30 分钟 | 约 `280px`，固定 |
| 隐藏副图 | 使用行情栏之外的全部空间 | 隐藏 | 约 `280px`，固定 |

中间副图标题区提供 `[分时] [30m]` 切换。该选择只存在于当前 App 会话，不写入布局偏好，也不随“显示/隐藏副图”一起持久化。30 分钟数据不可用时保留用户选择，显示空态和对应 warning，不自动切回分时。

布局切换必须满足：

- 不更换当前股票；
- 不变更实盘/回放模式；
- 不重置回放日期、时间或进度；
- 不重置图层开关；
- 不重置 5 分钟图和 30 分钟图的缩放、拖动位置与跟随/手工浏览状态；
- 不卸载或重建行情栏；
- 隐藏后恢复副图时，若当前选择为分时，仍展示目标日完整交易时段轴（见第 6.2 节），不恢复为局部缩放窗口。

应在 React 状态层保存 5 分钟图表可见范围等持久化所需数据，不应依赖 Lightweight Charts 组件恰好没有被卸载来保持状态。分时图不持久化局部时间窗口。

## 6. 图表组与联动边界

工作台包含相互独立的图表同步组：固定的 5 分钟主图组，以及中间副图中的分时组或 30 分钟组。同一时刻只显示其中一组副图。

### 6.1 5 分钟图表组

```text
5 分钟价格图
├── 5 分钟 VOL
└── 5 分钟 MACD
```

组内同步可见时间范围、水平缩放、水平拖动与十字光标时间。主图可显示 K 线、BOLL、MA5/MA10/MA20/MA30/MA60、笔、笔中枢、CZSC 买卖点与手工成交点。未闭合的动态 5 分钟 K 保留原有涨跌色相，通过降低实体、边框和影线透明度表示；不显示“形成中”文字，不使用虚线、额外图标或动画。

默认可见窗口采用宽度驱动的满轴规则：以 5 分钟价格图扣除坐标轴、边距后的实际绘图区宽度，结合统一的目标 K 线槽位宽度，计算当前可以容纳的最近 N 根 K 线。图表以最新 K 线为右边界；当天 K 线不足 N 根时继续显示上一交易日及更早交易日，直到铺满时间轴或已加载历史确实不足。VOL、MACD 和全部叠加图层必须使用与价格图完全相同的 N 根范围和水平坐标。

5 分钟图一个完整交易日为 48 根 5 分钟 K 线（早盘 24 根 + 午盘 24 根）。N 的上下限按跟随状态区分：跟随最新状态下，N 不得少于 72 根（1.5 个交易日），即使窗口宽度不足以容纳也应夹紧到该下限，确保至少展示一天半的行情；用户手动缩放浏览时，N 不得少于 48 根（1 个交易日），允许用户放大到一天但不能更少。两种状态下 N 的上限均为 360 根。

由于跟随下限（72）高于手动下限（48），用户手动缩放至 48–71 根后纯平移回到最新边缘时，会先以当前跨度进入跟随状态，直到下一次刷新或布局变化时才按跟随规则重算为 ≥72 根。此瞬态行为是预期的：贴边瞬间立即跳变到 72 根的体感更差。

5 分钟组使用按实际 K 线序号排列的逻辑时间轴。午休、隔夜、周末、节假日和停牌时段不产生空槽或成比例的时间空白；跨日处通过时间轴标签明确显示日期。笔、中枢或指标线即使起点位于可见窗口左侧，只要其有效部分进入当前窗口，进入窗口的部分仍应正确显示。

首次加载、切换股票、进入回放初始画面，或图表仍贴近最新数据边缘时，视为“跟随最新”状态。此时窗口尺寸或三种布局改变后，应按新的绘图区宽度重新计算 N，并继续右对齐满轴显示。用户主动缩放或向左拖动后进入手工浏览状态。布局切换、同一根动态 K 的 OHLCV 刷新应保留其逻辑可见范围，不得强制跳回最新端。用户重新移动到最新边缘后可恢复跟随最新行为。

实盘交易盘中，5 分钟图在稳定 Live Session 内向前追加一根真实新 K（最后时间戳严格变晚，且旧序列仍是新序列前缀）时，无论当前为跟随或手工浏览，都必须切回跟随最新：按绘图区密度重算 N（遵守跟随下限 72 与上限 360），并将可见范围右端精确对齐到最新 K（`to = length - 1`），不允许最新 K 停在视图右侧之外。同根动态更新、左侧历史 prepend 不触发该强制贴右。换股或整段 Live Session 替换应走首次加载语义（跟随最新），不得继承上一 Session 的手工范围；不走“新增 K 强制贴右”分支。后台期间若最后时间戳已前进或 Session identity 已变化，恢复前台后同样忽略旧手工快照并贴右；后台期间无新 K 且 Session 未变时仍保留原有手工范围。回放模式与分时图保持原有视口语义，不受上述实盘强制贴右规则影响。

### 6.2 1 分钟图表组

```text
1 分钟价格 + 分时均价线（VWAP）
├── 1 分钟 VOL
└── 1 分钟 MACD
```

组内同步十字光标时间，并始终共享同一条全日交易时间轴。垂直十字光标应在价格、VOL 和 MACD 三行中对齐，并显示同一分钟的对应数值。

成交量或成交额缺失不改变图表组尺寸，也不阻止价格图和不依赖量额的指标显示：

- 1 分钟和 5 分钟 VOL 使用同一规则：整个当前渲染视口没有可用成交量时，VOL 区域不绘制柱或均线，在绘图区居中显示中性灰色 `N/A`；用户缩放或拖动到至少包含一个有效成交量的视口后，恢复绘制有效柱，缺失点仍留空。分时固定全日轴时只检查已发布 bar，尚未发生或回放尚未推进到的未来槽位不参与判定。该视口判断只影响渲染，不改变快照 warning；
- 只有部分时点缺少成交量时，缺失点留空、不补零、不跨缺口连接 VOL MA，十字光标移动到该时点时显示 `N/A`；
- VWAP 所需的成交量或成交额缺失时，分时价格仍正常绘制；VWAP 全部不可用时在该线的图例值位置显示 `N/A`；当日累计前缀第一次出现缺口后，曲线从该点起断开且后续十字光标值均显示 `N/A`，不得在缺口后恢复成新的累计段；
- 数值 `0` 仅用于数据源明确报告零成交，`N/A` 表示无法获得，两者在视觉和 tooltip 中不得混淆。

#### 6.2.0 分时时间轴与视口

分时图展示**目标交易日当日**的行情，不是 5 分钟那种“宽度驱动、右对齐最近 N 根”的视口。

水平时间轴固定为当日完整交易分钟序列：

```text
09:30 → … → 11:30 → 13:00 → … → 15:00
```

沪深正常交易日约 242 个分钟槽位（早盘与午盘连续排列，午休不留成比例空白）。未来尚未发生的分钟以空白槽位占位，使右边界始终对应收盘 `15:00`，左边界始终对应开盘 `09:30`。

显示规则：

- 时间从左向右推进：`09:30` 在左，`15:00` 在右；
- 已发生行情从左向右逐步填入；每新增 1 分钟，只在对应槽位写入数据，**不得**把整段曲线贴到绘图区右缘，也不得每分钟整体向左推移；
- 进入午后后，上午已发生数据继续保留在轴上，不截断、不丢弃；
- 可见范围锁定为上述全日交易分钟，不按绘图区宽度重算 N，也不使用 5 分钟的“跟随最新 / 手工浏览”状态机；
- 禁用水平缩放与水平拖动，避免把早盘滚出屏幕或把右缘误钉在最新有值分钟上；
- 不得对分时开启会把右缘钳制到“最后一根有值 K”的边缘锁定（该类钳制仅适用于 5 分钟组）。

实盘追加与回放推进都只填充已发生分钟；内部视口与 Lightweight Charts 实际可见逻辑范围都必须保持全日左锚，而不是右跟随。

#### 6.2.1 分时价格图坐标计算

设前一交易日收盘价为 `P0`、开盘价为 `O`、当日截至当前最高价为 `H`、最低价为 `L`。开盘前或尚无有效分钟行情时，初始范围为 `±1%`；取得开盘价后：

```text
initial_range = max(1%, abs(O / P0 - 1))
```

盘中半轴范围 `R` 按当日截至当前全部有效 1 分钟行情计算，并且只扩不缩：

```text
R = max(previous_R, initial_range, abs(H / P0 - 1), abs(L / P0 - 1))
```

`P0` 始终位于垂直中心，纵轴上下沿为：

```text
y_max = P0 * (1 + R)
y_min = P0 * (1 - R)
```

中轴到上下沿各四等分，刻度比例为：

```text
+R, +3R/4, +R/2, +R/4, 0, -R/4, -R/2, -3R/4, -R
```

价格刻度按 `price = P0 * (1 + ratio)` 计算。最大偏离侧不增加百分比留白，也不取整到固定涨跌幅档位。价格回落不收缩纵轴；分时水平视口本身固定为全日交易轴，不随局部浏览变化。切换证券或交易日时重置；回放向后定位时按开盘至新游标的数据重新计算。

例如，`600584` 前收价为 `65.41`、当日截至当前最高价为 `70.59` 时：

```text
R     = 70.59 / 65.41 - 1 = 7.92%（显示值）
y_max = 70.59
y_min = 65.41 * (1 - R) = 60.23
```

因此 `65.41` 位于纵向正中央，上下沿分别为 `70.59` 和约 `60.23`。

### 6.3 30 分钟图表组

```text
30 分钟价格图
├── 30 分钟 VOL
└── 30 分钟 MACD
```

30 分钟图与 5 分钟图使用相同的三行结构、图层开关、Tooltip 字段和成交标记规则，但消费独立的 `market.bars_30m`、`indicators.thirty_minute` 和 `chan_analysis_30m`。图上显示的是 30 分钟笔中枢。当前未完成的 30 分钟 K 只用低透明度表达，不增加文字。

视口规则复用 5 分钟组：跟随最新至少 72 根、手工缩放至少 48 根、最多 360 根。会话内使用独立的 `chartViews.thirtyMinute` 槽位，与分时视口互不覆盖。切股或更换 Session 时清空。30 分钟组与 5 分钟组不同步十字光标。

### 6.4 组间独立

5 分钟图表组、1 分钟图表组和 30 分钟图表组之间不同步时间轴、缩放、拖动或十字光标。任一区域的操作不得带动另一区域。

自动刷新只增量更新数据：

- 5 分钟组：不得把手工浏览视口强制重置到最新端；若仍处于跟随最新，可随新 K 自然右对齐前滚；
- 分时组：始终保持全日交易轴左锚；新分钟只向右填充槽位，不得改成右跟随或整体左移。

## 7. 顶部工具栏

顶部工具栏始终可见，只包含代码输入、股票名称和实盘/回放双态按钮：

```text
[代码输入]  [股票名称]                         [实盘 / 回放]
```

代码输入和股票名称左对齐，双态按钮右对齐。代码输入支持证券代码、名称和拼音首字母模糊搜索，用户必须从匹配结果中选择。选中后，输入框显示标准代码，例如 `600584`，右侧显示证券名称，例如“长电科技”；未选股时名称位置保持空白。

实盘/回放是一个双态按钮，启动时默认为实盘。每点击一次在两种模式间切换，并以选中背景清晰表示当前模式。模式按钮不使用红绿色。

5 分钟主图右上角的叠加开关必须包含：

```text
MA5 / MA10 / MA20 / MA30 / MA60 / 笔 / 笔中枢
```

原型图中只画出 `MA5 / MA10 / MA20` 是视觉简化，不改变 PRD 规定的五条均线。均线按钮的默认状态、颜色和持久化规则以 PRD 为准。BOLL 在当前产品中默认显示，不设置独立开关。

## 8. 回放操作面板

回放操作面板位于三栏行情工作区下方、T+0 成交折叠栏上方，并横跨三栏完整宽度。实盘模式下完全隐藏且不保留空白高度；回放模式下自动显示。

未开始回放时，面板显示回放日期和“开始回放”。开始后，控件单行排列，面板高度基准为 `56px`：

```text
[播放/暂停]  09:30 ━━━━━● 10:23 ━━━━━━━━ 15:00  [前进 1 分钟]  [1× ▾]
```

进度条占用该行的主要水平空间，当前回放时刻跟随滑块显示。开始拖动时自动暂停，释放后停留在目标时点。将进度条拖到最左端即回到目标日开盘，不另设“重新开始”按钮。倍速使用一个下拉列表选择 `1× / 2× / 5× / 10×`。

降级为 5 分钟回放时，单步按钮改为“前进 5 分钟”。单步按钮推进到下一根实际 K；不存在下一根时禁用。分时区保留三行尺寸和边框，统一显示一个居中的中性灰色“无 1 分钟数据”空状态，不使用警告色或图标。

“无 1 分钟数据”只用于缺少可回放的 1 分钟价格 K 线。若 1 分钟 OHLC 可用而仅
`volume` / `amount` 缺失，不得显示该整组空状态，也不得降级到 5 分钟回放；价格与
MACD 继续展示，VOL / VWAP 按 §6.2 的 `N/A` 规则局部降级。

## 9. 最右行情栏

行情栏持续可见，它的内容按以下视觉优先级组织：

1. 日 K；
2. 「行情数据」标题；
3. 最新价和涨跌幅；
4. 今日开盘、最高、最低和昨收；
5. 成交量和成交额；
6. 量比和实时换手率；
7. 委比；
8. 「数据截止」元信息行（字段网格下方，单独一行，右对齐）。

委比只表示当前盘口委托量的相对状态，视觉权重应低于成交量、量比和换手率。不使用强调色将委比表现为买卖信号，不为它增加解读或建议。

「数据截止」取自实时行情快照的更新时间，格式为 `数据截止  MM-DD HH:MM:SS`，不使用 App 的请求完成时间；尚无快照时显示 `数据截止  --`。该行不是行情字段，不得放入字段网格，也不得表现为整页工作台或日 K 的全局时间。占位符按状态而不是按区域选择：已有当前快照、但字段确认不可获得或无法可靠计算时显示 `N/A`；尚无快照、正在加载或回放尚未到达对应时点时显示 `--`。成交量、成交额、量比、委比和换手率均遵守此规则，不得因字段缺失改变行情栏布局。

行情栏的累计成交量和成交额优先显示与当前证券、交易日和快照时间匹配的 Provider 权威
Quote 非空值；即使分钟序列存在缺口，也不得把该权威值强制改成 `N/A`。这只影响行情栏，
分钟 VOL、分钟派生累计值和相应 warning 仍按分钟数据独立呈现。Replay 不得显示游标之后
的 Quote。

日 K 区域高度基准为 `220px`，默认显示最近 60 个实际交易日并包含当天正在形成的动态日 K。当前产品不要求日 K 独立缩放或拖动；日线 MA5 和 MA20 默认关闭。

## 10. T+0 成交折叠栏

T+0 成交区域位于工作台底部并横跨全宽，默认收起。收起时仅显示：

- `T+0 成交` 标题；
- 当日记录笔数等简短摘要；
- `录入成交` 入口；
- `历史交易记录` 入口；
- 展开/收起操作。

用户录入成交、查看记录或复盘时再展开详情。展开后使用向上覆盖的底部 Drawer，高度为 `min(320px, 40vh)`，内容超出时在 Drawer 内部滚动。展开不通过压缩或重建图表实例实现，也不得把交易记录变为常驻第四列。

折叠栏展开或收起时：

- 不改变当前布局模式；
- 不改变图层开关；
- 不重置图表缩放与拖动位置；
- 不改变回放进度；
- 不隐藏最右行情栏。

实盘模式展示本地持久化的当前股票、当前日期成交记录，并提供录入与维护入口。回放
模式只读展示本地数据库中当前股票、目标日期且不晚于回放游标的真实成交；游标回退
时晚于新游标的标记再次隐藏。成交标记是独立覆盖层，不参与主价格轴自动缩放，
展开/收起成交区域或刷新成交不得重建行情图表实例。

Replay 底部栏不显示“录入成交”，但保留“历史交易记录”入口。Replay 中的历史对话框隐藏编辑和删除操作，只允许浏览记录和进入只读历史日图。目标 `symbol + trade_date` 就绪或改变时只查询一次全天成交；播放、单步和 seek 只做本地游标过滤。当前 scope 收到成交变化、服务 generation 改变或重连时才重新查询。

## 11. 窗口与目标设备约束

布局首先面向 13 英寸 MacBook Air M1 和 14 英寸 MacBook Pro M3 的内置屏幕。在系统默认显示缩放下，必须满足：

- 无需横向滚动即可查看两个图表区和最右行情栏的核心内容；
- 顶部核心操作不被遮挡；
- 回放控制区可完整操作；
- 图表标题、时间轴和数值可读；
- 最右行情栏不被压缩成不可读状态；
- 成交折叠栏默认不长期占用看图空间。

窗口缩小到低于可用最小尺寸时，Electron 窗口应优先设置合理的最小宽高，而不是通过隐藏行情字段或核心操作来强行适配。具体最小像素值在 Electron 原型上以两类目标设备验证后固定。

## 12. 状态保持

以下状态应保存在前端工作台状态或本地偏好中，不由图表组件的生命周期隐式决定：

| 状态 | 布局切换 | 实盘/回放切换 | App 重启 |
| --- | --- | --- | --- |
| 最后选择的股票 | 保留 | 共用当前股票 | 保留 |
| 布局模式 | 当前选择 | 保留 | 保留 |
| 图层开关 | 保留 | 保留 | 保留 |
| 5 分钟图表可见范围 | 保留 | 保留 | 可不保留 |
| 5 分钟跟随最新/手工浏览状态 | 保留 | 保留 | 默认跟随最新 |
| 分时时间轴视口 | 始终全日交易轴（见 §6.2.0），不持久化局部窗口 | 同左 | 同左 |

## 13. 加载、空状态与失败状态

- 首次未选股时，主工作区保持空白图表框架；顶部代码输入框即为选股入口；
- 股票切换或首次加载时，显示简单 Loading 动画和“正在加载历史行情并计算图表…”；
- 初始全量数据、CZSC 结构和指标就绪后一次性显示工作台，不在初始加载期间反复改变图表范围；
- 后台刷新失败时保留最后一次成功数据，在工作台显示简短状态和“重试”；
- 用户主动操作失败时显示弹窗和“重试”，不清空当前成功图表；
- 5 分钟降级回放保留分时区，并在原位显示“无 1 分钟数据”。
- OHLC 价格可用但成交量或成交额不可用时不显示全局失败横幅或 toast；受影响的 VOL、成交额或 VWAP 区域显示 `N/A`，其他图表继续工作；`volume_data_unavailable` / `amount_data_unavailable` 默认仅用于驱动局部降级、无障碍说明和诊断日志，不另占工作台空间；
- 首期无障碍实现不得只停留在日志：每个显示 `N/A` 的行情值或图表区域必须设置包含字段名、`N/A` 和“数据不可用”的可访问名称，例如 `aria-label="成交量：N/A（数据不可用）"`；不要求为量额 warning 增加全局 live region、横幅或 toast；
- 失败文案必须说明真实对象和结果。只有 Python 本地服务确实未启动、退出、正在重启或不可达时才显示“本地服务尚未就绪”；数据字段缺失或回放准备失败不得使用该文案；
- “重试”执行与错误类型匹配的动作：服务错误重启或重连服务，行情获取错误重新获取数据，Replay 准备错误重新准备 Replay。服务已经 ready 时不得用重连代替数据重试。

## 14. 组件边界建议

为避免布局、图表和业务状态耦合，前端可按以下职责划分组件，具体命名可在技术方案中调整：

```text
T0Workbench
├── WorkbenchToolbar
├── WorkbenchGrid
│   ├── FiveMinuteChartGroup
│   ├── IntradayChartGroup
│   └── MarketSidebar
├── ReplayControls
└── TradeDrawer
```

`WorkbenchGrid` 只负责三列三行的尺寸与布局状态；图表组负责 Lightweight Charts 实例、系列和组内联动；工作台状态层负责数据、模式、可见范围和用户偏好。

## 16. 原型说明

已确认的原型表达以下布局意图：

- 5 分钟与分时区均按价格图、VOL、MACD 三行排列；
- 两个图表区的三行严格对齐；
- 最右行情栏固定；
- 布局切换不改变最右行情栏；
- 成交记录默认折叠为底栏；
- 委比可展示，但其视觉与信息权重低于成交量、量比和换手率。

原型中的标题水印、页面外解释文字和演示行情数值仅用于表达设计，不是实际产品内容或固定数据。
