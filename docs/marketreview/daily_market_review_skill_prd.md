# 每日市场复盘 Skill PRD

- 文档状态：Draft
- Skill 名称：`daily-market-review`（暂定）
- 所属项目：Stock Pilot
- 当前版本：V1 总体复盘
- 指标附录：[《每日市场复盘 Skill PRD》附录：指标说明与统计口径](资本市场复盘指标说明与统计口径.md)

## 1. 产品目标

每日市场复盘用于整理、补充和展示指定已收盘交易日的资本市场数据。V1 先做成一份可靠的日度复盘账本，再逐步升级自动数据源。

数据库是长期积累的数据资产，不只服务于 Skill，也必须能够直接支持未来的 Stock Pilot 应用。

本次只设计 `daily-market-review`。其他 Skill 的范围与触发词不在本文档处理。

## 2. 职责边界

| 层 | 职责 |
| --- | --- |
| `packages/marketdata` | 交易日历、行情 provider 和原始行情能力 |
| `packages/marketreview` | 数据表结构，以及复盘原子字段和每日涨跌停事件的简单保存、更新、删除与查询 |
| `daily-market-review` Skill | 理解用户请求，取得数据，完成市场、代码、交易日期、涨跌幅限制等业务校验，调用 package 写入；读取后统计并格式化展示 |

约束：

- Skill 负责取得和校验复盘数据，也负责读取后的统计与展示，但不直接操作 SQLite。
- Skill 和未来应用统一调用 `packages/marketreview` 的接口读写复盘数据。
- 行情类数据优先复用 `packages/marketdata` 的稳定接口；`packages/marketreview` 不负责外部数据采集或复盘采集编排。
- `packages/marketreview` 将调用方提交的数据视为待保存内容，不重复判断市场事实是否正确。SQLite 只承担字段类型、可空性、行身份唯一性和事务安全等结构性职责。
- 数据可能录错；用户在查看时发现问题后，可以让 Skill 修订或覆盖。数据库不承担事实核验职责。
- 腾讯指数 K 线里的 `amount` 暂不等同于交易所全市场成交额。在没有专门 provider 和对照测试前，不将成交额列为自动项。

## 3. 功能范围

### 3.1 V1：总体复盘

整理和展示指定交易日的以下数据：

| 类别 | 指标 |
| --- | --- |
| 涨跌停 | 有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板、炸板率 |
| 市场宽度 | 回头波数、中位数涨跌幅、上涨家数、下跌家数、涨跌停比 |
| 连板 | 首板数、连板数、连板率、最高板、最高板代表、按实际高度动态分组的数量 |
| 两融 | 上海两融余额、深圳两融余额、北京两融余额、两融余额合计 |
| 指数 | 上证指数、深证成指、创业板指的点位、涨跌点数和涨跌幅 |
| 成交额 | 上海、深圳、创业板、北京及合计成交额；创业板单独展示但已包含在深圳成交额中 |
| 市场规模与估值 | 总市值、流通市值、上海 PE、深圳 PE、创业板 PE、全市场 PE |
| 平均股价 | 平均股价 |

经参考数值比对确认，原表中的“成交量”实际是成交额。系统字段和展示名称统一使用“成交额”。

市场 PE 不由系统计算，直接记录同花顺在指定交易日展示的市盈率，不使用各市场 PE 进行加权或算术平均。上海 PE 对应同花顺 `000001`，深圳 PE 对应同花顺 `399001`。以 2026-08-21 为例，`000001` 市盈率为 `17.00`，`399001` 市盈率为 `30.67`。V1 直接保存数值，不自行解释为 TTM 或静态 PE。

平均股价不由系统根据个股价格计算。同花顺对应代码为 `830000`，申万宏源对应代码为 `880003`。V1 由 Skill 取得或请用户补充，未取得时留空。

市场宽度覆盖上海、深圳和北京市场，证券软件统计范围包含停牌和无成交股票。上涨家数、下跌家数、中位数涨跌幅和回头波数 V1 直接记录证券软件展示的数值，由 Skill 取得或请用户补充；未取得时留空。回头波定义为 `最高价 ÷ 收盘价 - 1 > 10%`，严格使用 `>`；V1 不遍历全市场重新计算。

V1 只处理收盘后的日度数据。中午涨停、中午成交额、开盘成交额和开盘情绪暂不实现。

V1 保存每日涨跌停事件：Skill 将取得并完成业务校验的数据按交易日、股票和方向写入，并记录收盘是否仍处于对应涨跌停价格。数据库不判断某日名单是否完整，也不判断事件内容是否符合真实行情；缺少的事件按当前数据库中不存在处理，之后可补录或修订。展示时，Skill 根据已保存事件统计有效涨停、涨停炸板、打开跌停、收盘跌停、首板和连板等指标。

### 3.2 V2 预留：每日梯队

Skill 可根据每日涨停事件沿交易日时间轴整理首板及各连板高度，再补充梯队展示字段。不另建重复的连板分布表或日度聚合表。初始化或数据断档后，可在某条有效涨停事件上保存可选的 `streak_height_anchor`，表示 Skill 取得的该股票在该事件所属交易日的实际连续涨停高度。数据库原样保存该值，不校验其事实正确性或与其他日期是否一致。

计划包含：股票代码和名称、连板高度、行情走势、所属板块、炒作概念或涨停原因、成交额、竞价、开盘涨幅、换手率、是否龙头和备注。

跌停股票和涨停炸板股票不属于连板梯队，但保留在同一份每日涨跌停事件数据中，可作为独立名单展示。

### 3.3 V3 预留：情绪周期图

根据已有总体复盘和每日涨跌停事件生成跨交易日视图，主要展示每日最高连板数、最高板代表、有效涨停数量、连板数量、涨停炸板、打开跌停、收盘跌停和各板高度数量。

情绪周期图是展示视图，不单独保存重复的日度聚合结果。

总体复盘表如需紧凑展示，Skill 可以将 11 板及以上合并为 `11板+`；展示统计按实际高度动态分组，不生成 `board_1` 至 `board_11_plus` 等固定字段。情绪周期图按每日实际高度分组。

## 4. V1 指标出数合同

每个指标必须属于以下三类之一，并作为验收依据。

### 4.1 Skill 自动获取

当前只承诺：

- 上证指数日 K（规范标识 `sh000001`）
- 深证成指日 K（规范标识 `sz399001`）
- 创业板指日 K（规范标识 `sz399006`）

Skill 通过 `packages/marketdata` 的行情能力取得日 K，再将当日收盘点位和前收盘点位作为普通原子字段提交给 `packages/marketreview`。只提交成功取得且校验通过的完整指数点位对；获取失败的指数不进入本次 patch，因此已有记录保持原值，新记录对应字段留空。不得用其他日期数据顶替。

### 4.2 读取后统计

不重复入库。Skill 从 `packages/marketreview` 读取原始字段和事件后统计：

- 有效涨停、20% 涨停、打开跌停、收盘跌停和涨停炸板
- 炸板率、涨跌停比
- 首板数、连板数、连板率、最高板、最高板代表、各高度数量
- 两融余额合计
- 成交额合计
- 三只指数的涨跌点数和涨跌幅

成交额合计 = 上海成交额 + 深圳成交额 + 北京成交额。创业板成交额已包含在深圳成交额中，只作为单独指标展示，不重复计入合计。

统计结果只基于当前已保存的事件；Skill 不推断事件是否遗漏。历史涨停事件或高度锚点被补充、修正后，下次显示时重新统计首板、连板高度和连板率。

### 4.3 Skill 获取或用户补充

- 每日涨停和跌停事件
- 上涨家数、下跌家数、中位数涨跌幅、回头波数
- 上海 / 深圳 / 北京两融余额
- 上海 / 深圳 / 创业板 / 北京成交额
- 总市值、流通市值
- 上海 PE、深圳 PE、创业板 PE、全市场 PE
- 平均股价

Skill 可通过 API、网络查询、询问用户或其他可用方式取得这些数据。需要用户补数时，一次性给出带单位的 YAML 或表格模板，不逐项对话。用户可以暂时跳过；新记录中跳过的字段保存为空值，不得使用 `0` 或前一交易日数据代替。已有记录的跳过语义见第 7.5 节。

## 5. 总体复盘操作

### 5.1 写入复盘

用户可以请求：

> 生成今天的总体复盘。

或者：

> 生成 2026-08-21 的总体复盘。

用户可在任意日历日发起请求（包括周末和节假日）。正式记录的业务日期必须是已收盘交易日，见第 9 节。

Skill 可通过 API、网络查询、询问用户或其他可用方式取得数据。需要用户补充时，一次性列出本次尚未取得的内容；用户可以跳过任何字段。

用户要求写入时，Skill 将本次已经取得或由用户提供的数据调用 `packages/marketreview` 写入。不要求所有指标齐全，不保存采集状态，也不为未取得的字段猜测数值。字段级 patch 规则为：

- 未提供字段：保留原值；
- 具体值，包括 `0`：更新；
- 显式 `null`：清空；
- 新记录中未提供的原子字段：保持 `null`。

### 5.2 每日涨跌停事件写入

涨停和跌停事件可以按交易日和方向批量提交，也可以按单股增删改。数据库不保存名单完整性状态，不要求上一交易日已有数据，也不阻止任意历史日期的补录。某日没有对应事件时，所有派生结果均按当前数据库中的零条记录计算。

示例：

```text
本次尚未取得以下数据（可跳过）：

- 上海两融余额（元）
- 北京两融余额（元）
```

用户提交后，Skill 校验数值和单位，再调用 package 保存。所有数量字段均为可空整数：`null` 表示缺失，`0` 表示调用方提交的数量为零。数据库不判断该数值是否符合真实市场。最终展示遵循第 6 节：缺失值留空，已保存的 `0` 必须展示。

涨跌停事件的最小 YAML 输入示例：

```yaml
trade_date: 2026-08-21
price_limit_events:
  - market: sh
    code: "600519"
    name: 贵州茅台
    direction: up
    closed_at_limit: true
    limit_rate_bp: 1000
    streak_height_anchor: 4
```

事件记录存在即表示盘中曾触及对应方向的涨跌停价。`direction=up, closed_at_limit=true` 表示有效涨停，`false` 表示涨停炸板；`direction=down, closed_at_limit=true` 表示收盘跌停，`false` 表示打开跌停。可选的 `streak_height_anchor=4` 表示该股票在 `2026-08-21` 当天实际为四板，包含当天；它不是昨日高度，也不是下一日的起始值。

### 5.3 显示复盘

用户要求显示时，Skill 只读取数据库并格式化展示，不自动取数、不追问缺失数据、不判断复盘是否“完整”。总体复盘和涨跌停事件按交易日期组合读取：只要任一类数据存在，就返回当日视图；没有 `daily_market_review` 行时原子字段留空，但仍展示已保存的涨跌停事件及其派生指标。两类数据都不存在时，显示“无复盘数据”。

Skill 读取原始字段和事件后，按第 4.2 节统计并按类别格式化展示。读取和展示不修改数据库。

涨跌停比使用“有效涨停数 : 收盘跌停数”的方向展示，不使用百分数。两边都大于 0 时，将较小的一边归一化为 1，倍数保留两位小数：

- 有效涨停 58 只、收盘跌停 15 只，显示 `3.87:1`
- 有效涨停 4 只、收盘跌停 15 只，显示 `1:3.75`
- 两边相等，显示 `1:1`
- 只有一边为 0 时保留真实数量，显示为 `12:0` 或 `0:12`
- 两边都为 0 时，两项数量分别显示 `0`，涨跌停比留空
- 任一基础数据缺失时，涨跌停比留空

### 5.4 保存与查看

同一个交易日只保存一份总体复盘。再次执行时按字段级 patch 更新，不创建重复记录。

用户可以请求查看已保存的历史总体复盘。查询走 `packages/marketreview` 读取原子字段和事件，Skill 再统计和格式化；查询本身不修改数据库。

## 6. 展示方式

总体复盘按类别使用简单表格展示：

| 指标 | 数值 |
| --- | --- |
| 有效涨停（只） | 52 |
| 炸板率 | 18.75% |
| 上海成交额（亿元） | 8,432.16 |

展示要求：

- 只展示指标和值；
- 单位写在指标名称或数值中；展示层将库内的元换算为亿元或万亿元，将小数形式的比率换算为百分数；
- 不展示采集方式或更新时间；
- 没有对应数据时单元格留空，不显示 `—`、`0` 或其他占位符；
- 已确认的数值为 0 时必须显示 `0`，不能按缺失数据处理；
- 某日没有对应涨跌停事件时，相关事件数量按 `0` 展示；
- 连板梯队按实际派生高度动态分组，不生成 `board_1`、`board_2` 等固定字段；
- 不同类别分别展示。

## 7. 数据存储

### 7.1 数据库定位

Skill 和未来应用必须通过 `packages/marketreview` 读写数据库。

复盘数据复用现有 Stock Pilot runtime，默认路径：

```text
<workspace>/stockpilot/db/market_review.sqlite3
```

- Skill 安装目录不保存用户数据；
- 不新建 `~/.stockpilot/daily-market-review/` 第三套目录；
- 可通过现有 runtime 配置修改数据目录。
- 应用尚未上线，当前 schema 变更按新建数据库处理，不设计旧库迁移或兼容读取。

数据库只保存调用方提交的复盘原子指标和触板事件；事件可带一个可选的当日实际连板高度锚点。数据库不保存名单完整性、数据来源、采集方式、网页证据、候选值或展示汇总字段。Skill 负责通过 API、网络查询或询问用户取得并校验数据；数据库既不关心数据的取得方式，也不判断数据事实是否正确。V2 / V3 不增加重复的日度聚合表。

### 7.2 单位

数据库统一使用标准单位：

| 类别 | 存储 | 展示 |
| --- | --- | --- |
| 成交额、市值、两融余额 | 元 | 亿元或万亿元 |
| 百分比类指标（中位数涨跌幅、炸板率、连板率、指数涨跌幅等） | 小数，例如 `0.1875` | 百分数，例如 `18.75%` |
| 指数点位、PE、平均股价 | 原单位数值 | 原单位，按附录保留小数位 |

两融按其业务交易日归属写入对应交易日，即使实际要到 T+1 才公布。不得拿前一日余额冒充当日数据。

### 7.3 核心数据表

| 数据表 | 用途 |
| --- | --- |
| `daily_market_review` | 每个交易日一条总体复盘；只保存原子指标 |
| `daily_price_limit_event` | 一只股票在一个交易日触及一个方向的涨跌停价时一条记录，保存方向、收盘状态、涨跌幅限制和可选高度锚点 |

`daily_price_limit_event` 使用「交易日期 + 市场 + 6 位代码 + 方向」作为唯一键，允许极端情况下同一股票同日分别触及上下限。涨跌停事实独立于总体复盘存在，删除 `daily_market_review` 不删除同日涨跌停事件。

从业务上可以把事件数据理解为 `limit[交易日期][方向][市场 + 股票代码]`：先按交易日分组，再在当日区分涨停方向和跌停方向，最后取得具体股票事件。但 SQL 表不保存嵌套数组，而是将每只股票的每个触板方向平铺为一行。例如：

| `trade_date` | `market` | `code` | `name` | `direction` | `closed_at_limit` | `limit_rate_bp` | `streak_height_anchor` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `2026-08-21` | `sh` | `600001` | 示例股份 | `up` | `true` | `1000` | `2` |
| `2026-08-21` | `sz` | `300001` | 示例科技 | `up` | `false` | `2000` | `null` |
| `2026-08-21` | `sh` | `600002` | 示例实业 | `down` | `true` | `1000` | `null` |
| `2026-08-22` | `sh` | `600001` | 示例股份 | `up` | `true` | `1000` | `null` |

查询某个交易日，就是筛选该日期的所有事件行；查询某日涨停方向，就是再增加 `direction=up` 条件。`created_at` 和 `updated_at` 是每行事件的数据库审计时间，不属于独立快照。数据库不建立每日或方向快照表，也不保存 `complete`、已确认零触板或未知等名单状态。

入库身份对齐 `packages/marketdata` 证券主数据已有的 `(market, code)` 模型：`market` 使用小写 `sh | sz | bj`，`code` 使用保留前导零的 6 位字符串。package 返回结果时可组合为 `<market>.<code>`，例如 `sh.600519`、`sz.000001`、`bj.830799`；展示时只显示 6 位代码。V1 写入 API 要求调用方明确提交 `market` 和 `code`，不依赖裸代码猜测市场。现有 `standardize_security_identity` 是只支持沪深的 T+0 合同，本功能不扩展或复制该合同。

Skill 应按第 10 节证券宇宙过滤事件，不提交恒为 `false` 的 `is_st`。package 和数据库不重复复核过滤结果，也不判断某交易日是否漏录股票。

`daily_market_review` 中的指数字段为各指数的当日收盘点位和前收盘点位，不保存涨跌点数和涨跌幅。两融和成交额只保存各市场原始值。有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板及全部连板汇总均不保存在该表中。

### 7.4 每日涨跌停事件

一条 `daily_price_limit_event` 的存在表示该股票当日盘中曾触及 `direction` 对应的涨跌停价：

| `direction` | `closed_at_limit` | 业务含义 |
| --- | --- | --- |
| `up` | `true` | 有效涨停，参与首板和连板计算 |
| `up` | `false` | 涨停炸板，不产生当日板数并中断连续性 |
| `down` | `true` | 收盘跌停 |
| `down` | `false` | 打开跌停 |

`limit_rate_bp` 使用整数基点保存当日适用限制，例如 10% 为 `1000`、20% 为 `2000`、30% 为 `3000`。事件表不保存 `touched_at_limit=true`，因为记录存在本身已经表达触板；也不保存普通 `streak_height`。

`streak_height_anchor` 是可空整数，业务上用于 `direction=up and closed_at_limit=true` 的事件，表示 Skill 取得的该股票在记录当天已经达到的实际连续涨停高度，包含当天。Skill 在写入前检查其输入形态；数据库只保存，不比较其他日期或行情数据来判断它是否正确。

展示连板高度时，当日有锚点就使用已保存锚点；否则上一交易日存在同一股票有效涨停事件时，在上一日展示高度上加一；否则按首板 `1` 展示。涨停炸板、未涨停或数据库中没有上一交易日有效涨停事件都会中断当前数据时间轴中的连续性。该规则只是基于库内数据的展示计算，不用于验证或阻止写入，也不产生高度未知状态。多个锚点即使不一致，数据库仍按调用方提交内容保存；用户查看后自行判断并修订。

### 7.5 同日重跑：保存与修订

同一交易日再次生成或补充时，不做整日覆盖：

| 本轮行为 | 结果 |
| --- | --- |
| 未提供某字段 | 保持原值 |
| 提供具体数值 | 更新，包括合法的 `0` |
| 显式提供 `null` | 清空该字段 |
| 新记录中跳过的字段 | 保存为空 |
| 事件列表 | 按事件唯一键保存；已有记录更新，没有则新增 |
| 单股事件修订 | 按交易日、股票和方向更新或删除事件 |

涨跌停事件不定义 `direction_replace`、`item_patch` 等业务操作模型。对外只提供直接、普通的保存、查询和删除能力；批量保存只是多行保存的便利接口。空列表表示本次没有行可保存，不代表完整快照，也不额外建立状态。

新增或更新时，Skill 整理 `market`、`code`、`name`、`direction`、`closed_at_limit`、`limit_rate_bp` 和可选的 `streak_height_anchor`，完成业务校验后提交。package 不再根据行情、历史事件或证券规则重复校验这些内容。数据库只执行基本持久化；同一批写入可使用普通事务，目的仅是避免数据库故障造成半批写入，不代表数据库确认数据正确。

### 7.6 数据库读写能力

共享数据层只需提供：

- 新增或 patch 指定交易日的总体复盘原子字段；
- 查询单个交易日或日期范围的原子字段；
- 删除指定交易日的总体复盘；涨跌停事件作为共享事实独立保留；
- 保存、更新和删除涨跌停事件；
- 查询单日或日期范围内的原始涨跌停事件；
- 组合查询单日的原子字段和事件；总体复盘或涨跌停事件任一存在即返回，二者都不存在才返回 `None`。

有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板、连板高度和其他展示汇总由 Skill 根据查询结果统计。它们不参与数据库写入校验。

## 8. 技术边界

- 复盘表结构、字段级保存、涨跌停事件持久化和 SQLite 查询放在 `packages/marketreview/`；
- 行情和交易日历复用 `packages/marketdata/`；
- 数据获取、业务校验、读取后统计和展示流程由 `skills/daily-market-review/` 负责；
- `packages/marketreview` 不提供 `auto_patch_indices`、`fetch_index_atoms` 或 `IndexFetchResult` 之类的外部采集编排接口；
- 数据库使用 SQLite；
- 公共字段使用 `snake_case`。

## 9. Skill 的交易日与收盘校验

V1 的 Skill 只为已收盘交易日生成正式记录。用户可以在非交易日运行 Skill，但 Skill 应将业务日期解析为交易日。该规则属于 Skill 的业务校验；repository 和 SQLite 不查询交易日历来拒绝写入。

- 未指定日期时，落到最近一个已收盘交易日；
- 用户显式指定非交易日：不落库，并提示最近交易日；
- 目标日为当日且尚未收盘：拒绝生成正式记录；
- 历史已收盘交易日可直接生成或补充；
- 暂以 A 股统一 15:00 作为日度复盘收盘边界。

当前 `packages/marketdata` 交易日历尚无独立北交所市场合同。V1 默认北交所与沪深交易日一致，统一使用沪深交易日判断 A 股复盘日期；若未来出现差异日期，V1 不允许单独为北交所开另一条当日记录，待后续扩展多市场日历合同。

## 10. 复盘证券宇宙与 ST 排除

V1 涨跌停与连板的证券宇宙为上海、深圳、北京交易所上市的人民币普通股票。Skill 获取数据时排除 B 股、ETF、基金、债券、可转债、退市整理股票、上市首日及当日无涨跌幅限制的股票，同时排除 ST 股票。该过滤不在 repository 或 SQLite 中重复执行。

具体口径：

- 排除交易日当日处于 `ST`、`*ST` 等特别处理状态的股票；
- 有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板均不统计 ST 股票；
- 昨日有效涨停分母和每日涨跌停事件也不统计 ST 股票；
- Skill 不主动提交 ST 股票事件；
- 连板高度只计算连续的、符合复盘证券宇宙条件的非 ST 涨停交易日；
- 股票进入 ST 状态时原连板连续性终止；以后撤销 ST 后再次涨停，应重新从一板起算；
- ST 判断以对应交易日的历史状态为准，不能使用股票当前名称或当前 ST 状态回填历史数据；
- 内部建议使用按交易日生效的 `is_st` 或证券状态字段，不依赖临时的名称字符串判断。

因此，所有涨跌停派生指标也自然排除 ST：

- 炸板率的分子和分母均不含 ST；
- 涨跌停比两侧均不含 ST；
- 连板率的分子与上一交易日有效涨停分母均不含 ST。

市场宽度、成交额、市值、PE 等直接录入或全市场口径的指标，仍以证券软件展示为准；Skill 提交每日涨跌停事件前按上述证券宇宙口径过滤。数据库不会复核该过滤是否正确。

### 10.1 涨跌停细分口径

- `20% 涨停` 统计创业板和科创板中适用 20% 涨跌幅限制且收盘涨停的非 ST 股票。
- 北交所适用 30% 涨跌幅限制的非 ST 股票，计入有效涨停、打开跌停、收盘跌停和涨停炸板等相应基础数量，但不计入 `20% 涨停`；V1 不另设 `30% 涨停` 展示项。
- 当日盘中打开后重新封住涨停且收盘仍为涨停，计入有效涨停，不计入涨停炸板。
- 当日曾触及涨停但收盘未封住，计入涨停炸板。

### 10.2 连板连续性

- 首板和所有连板都来自每日有效涨停事件；数据库不直接记录板数。
- 每一个连续交易日都必须属于上述证券宇宙并收盘涨停；停牌、收盘未涨停、进入 ST、进入退市整理期或出现无涨跌幅限制交易日，均中断连板。
- 炸板后回封并以涨停收盘，仍视为当日涨停，连板可以延续；收盘未封住则中断。
- 连板率固定使用「今日二板及以上非 ST 股票数 ÷ 上一交易日非 ST 有效涨停数」。
- 当日有效涨停事件没有锚点，且上一交易日不存在同一股票的有效涨停事件时，按当前已有数据计算为首板。
- 有效涨停事件可携带当日实际连板高度锚点；下一交易日继续涨停时从该高度加一，炸板或未涨停后重新起算。

### 10.3 V1 事件数据的责任

V1 保存 Skill 本次取得并完成业务校验的触及涨停或跌停股票，不声明某交易日名单完整，也不推断是否漏录。Skill 负责证券宇宙、市场、代码、方向、收盘状态和涨跌幅限制等业务校验；package 和数据库原样持久化提交内容，不复核行情事实、锚点一致性或历史连续性。没有某条事件时，展示统计按当前数据库中不存在该事件处理。

有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板和连板汇总不再接受独立手工聚合值，统一从事件计算，从数据结构上消除聚合值与个股名单不一致的问题。

在接入按交易日生效的证券状态合同前，`packages/marketreview` 不根据当前股票名称推断历史 ST 状态，也不声称能够独立复核调用方的历史证券宇宙过滤结果。

## 11. V1 验收标准

1. 用户未指定日期且在非交易日或盘前发起时，使用最近一个已收盘交易日；用户显式指定非交易日时不落库并提示最近交易日；用户显式指定尚未收盘的当日时拒绝生成正式记录。
2. 自动获取仅承诺三只指数的日 K；成功则写入收盘与前收盘，失败不覆盖原值、不用其他日期顶替。
3. 用户要求写入时，Skill 只写入本次取得或由用户提供的数据；复盘原子字段和涨跌停事件均允许后续补录，不保存名单完整性状态。
4. 涨跌停基础数量、炸板率、涨跌停比、首板与连板汇总、连板率、两融合计、成交额合计、指数涨跌点数和涨跌幅均由 Skill 读取后统计，不入库。
5. 数据库只保存原子字段；同一交易日重复执行不产生重复记录，并遵守字段级 patch。
6. 用户要求显示时，Skill 只读取和格式化已保存的复盘，不自动取数、追问或修改数据库；原子字段为 `null` 时留空。
7. 总体复盘按照八个类别以简单表格展示，表格只显示指标和值。
8. 默认数据库路径为 `<workspace>/stockpilot/db/market_review.sqlite3`。
9. 数据层支持总体复盘和涨跌停事件的简单新增、查询、更新与删除，支持按单日和日期范围查询，可被 Skill 之外的应用调用。
10. 涨跌停和连板指标只基于当前已保存事件计算；没有事件时相应数量为 `0`，系统不判断是实际为零还是尚未录入。
11. `daily_price_limit_event` 使用日期、市场、代码和方向作为唯一键；事件独立于总体复盘，删除总体复盘不删除同日事件事实。
12. 数据库不保存数据来源或采集方式。
13. `2026-08-21` 已由仓库沪深交易日历确认为已收盘交易日，前一交易日固定为 `2026-08-20`。黄金 fixture 至少包括连续多个交易日的涨停事件、当日跌停事件、首板、连板、涨停炸板、打开跌停、收盘跌停、初始化锚点和断档后锚点，以及所有派生指标预期结果。
14. 展示统计验收覆盖无前日事件按首板显示、前日有效涨停高度加一、炸板中断、锚点当天高度、锚点后的递推和断档后新锚点；锚点冲突不作为数据库拒绝写入条件。
15. 持久化验收覆盖事件新增、更新、查询和删除，以及数据库故障时批量写入不会留下半批数据；业务内容正确性由 Skill 和用户负责。

## 12. 暂缓范围

- 午间数据、开盘数据和情绪周期阶段判断不在 V1。
- 涨跌停事件、市场宽度、两融、市场成交额、市值、PE 和平均股价的专用自动采集 provider 不在 V1；Skill 仍可通过可用来源取得事件后提交。
