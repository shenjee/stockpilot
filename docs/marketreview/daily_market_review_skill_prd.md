# 每日市场复盘 Skill PRD

- 文档状态：Draft
- Skill 名称：`daily-market-review`（暂定）
- 所属项目：Stock Pilot
- 当前版本：V1 总体复盘
- 指标附录：[《每日市场复盘 Skill PRD》附录：指标说明与统计口径](资本市场复盘指标说明与统计口径.md)

## 1. 产品目标

每日市场复盘用于整理、补充和展示指定已收盘交易日的资本市场数据。V1 先做成一份可靠的日度复盘账本，再逐步升级自动数据源。

数据库是长期积累的数据资产，不只服务于 Skill，也必须能够直接支持未来的 Stock Pilot 应用。

本次只设计 `daily-market-review`。其他 Skill 的范围与触发词不在本文档处理。

## 2. 职责边界

| 层 | 职责 |
| --- | --- |
| `packages/marketdata` | 交易日历、行情 provider 和原始行情能力 |
| `packages/marketreview` | 指标合同、输入校验、字段级 patch、每日涨跌停事件快照、连板派生、读时计算、持久化和查询 |
| `daily-market-review` Skill | 理解用户请求，通过 API、网络查询、询问用户或其他可用方式取得数据，调用 package 写入并展示结果 |

约束：

- Skill 负责取得复盘数据，但不重复实现 package 中的校验和派生计算逻辑，也不直接操作 SQLite。
- Skill 和未来应用统一调用 `packages/marketreview` 的接口读写复盘数据。
- 行情类数据优先复用 `packages/marketdata` 的稳定接口；`packages/marketreview` 不负责外部数据采集或复盘采集编排。
- 腾讯指数 K 线里的 `amount` 暂不等同于交易所全市场成交额。在没有专门 provider 和对照测试前，不将成交额列为自动项。

## 3. 功能范围

### 3.1 V1：总体复盘

整理和展示指定交易日的以下数据：

| 类别 | 指标 |
| --- | --- |
| 涨跌停 | 有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板、炸板率 |
| 市场宽度 | 回头波数、中位数涨跌幅、上涨家数、下跌家数、涨跌停比 |
| 连板 | 首板数、连板数、连板率、最高板、最高板代表、1 至 10 板数量、11 板+数量 |
| 两融 | 上海两融余额、深圳两融余额、北京两融余额、两融余额合计 |
| 指数 | 上证指数、深证成指、创业板指的点位、涨跌点数和涨跌幅 |
| 成交额 | 上海、深圳、创业板、北京及合计成交额；创业板单独展示但已包含在深圳成交额中 |
| 市场规模与估值 | 总市值、流通市值、上海 PE、深圳 PE、创业板 PE、全市场 PE |
| 平均股价 | 平均股价 |

经参考数值比对确认，原表中的“成交量”实际是成交额。系统字段和展示名称统一使用“成交额”。

市场 PE 不由系统计算，直接记录同花顺在指定交易日展示的市盈率，不使用各市场 PE 进行加权或算术平均。上海 PE 对应同花顺 `000001`，深圳 PE 对应同花顺 `399001`。以 2026-08-21 为例，`000001` 市盈率为 `17.00`，`399001` 市盈率为 `30.67`。V1 直接保存数值，不自行解释为 TTM 或静态 PE。

平均股价不由系统根据个股价格计算。同花顺对应代码为 `830000`，申万宏源对应代码为 `880003`。V1 由 Skill 取得或请用户补充，未取得时留空。

市场宽度覆盖上海、深圳和北京市场，证券软件统计范围包含停牌和无成交股票。上涨家数、下跌家数、中位数涨跌幅和回头波数 V1 直接记录证券软件展示的数值，由 Skill 取得或请用户补充；未取得时留空。回头波定义为 `最高价 ÷ 收盘价 - 1 > 10%`，严格使用 `>`；V1 不遍历全市场重新计算。

V1 只处理收盘后的日度数据。中午涨停、中午成交额、开盘成交额和开盘情绪暂不实现。

V1 保存完整的每日涨跌停事件快照：只要符合复盘证券宇宙的股票在盘中曾触及涨停价或跌停价，就按交易日、股票和方向保存一条事件，并记录收盘是否仍处于对应涨跌停价格。首板、连板高度、有效涨停、涨停炸板、打开跌停和收盘跌停均由事件读时派生，不作为重复事实保存。

### 3.2 V2 预留：每日梯队

根据每日涨停事件向前匹配连续交易日，派生首板及各连板高度，再补充梯队展示字段。不另建重复的连板分布表或日度聚合表，也不持久化 `streak_height`。

计划包含：股票代码和名称、连板高度、行情走势、所属板块、炒作概念或涨停原因、成交额、竞价、开盘涨幅、换手率、是否龙头和备注。

跌停股票和涨停炸板股票不属于连板梯队，但保留在同一份每日涨跌停事件数据中，可作为独立名单展示。

### 3.3 V3 预留：情绪周期图

根据已有总体复盘和每日涨跌停事件生成跨交易日视图，主要展示每日最高连板数、最高板代表、有效涨停数量、连板数量、涨停炸板、打开跌停、收盘跌停和各板高度数量。

情绪周期图是展示视图，不单独保存重复的日度聚合结果。

总体复盘表为了紧凑展示，将 11 板及以上合并为 `11板+`；情绪周期图按每日实际高度分组，不做 `11板+` 合并。

## 4. V1 指标出数合同

每个指标必须属于以下三类之一，并作为验收依据。

### 4.1 Skill 自动获取

当前只承诺：

- 上证指数日 K（规范标识 `sh000001`）
- 深证成指日 K（规范标识 `sz399001`）
- 创业板指日 K（规范标识 `sz399006`）

Skill 通过 `packages/marketdata` 的行情能力取得日 K，再将当日收盘点位和前收盘点位作为普通原子字段提交给 `packages/marketreview`。只提交成功取得且校验通过的完整指数点位对；获取失败的指数不进入本次 patch，因此已有记录保持原值，新记录对应字段留空。不得用其他日期数据顶替。

### 4.2 读时计算

不入库，由 `packages/marketreview` 在读取时计算：

- 有效涨停、20% 涨停、打开跌停、收盘跌停和涨停炸板
- 炸板率、涨跌停比
- 首板数、连板数、连板率、最高板、最高板代表、各高度数量
- 两融余额合计
- 成交额合计
- 三只指数的涨跌点数和涨跌幅

成交额合计 = 上海成交额 + 深圳成交额 + 北京成交额。创业板成交额已包含在深圳成交额中，只作为单独指标展示，不重复计入合计。

任一组成字段或所需快照缺失时，对应派生结果留空，不得用 `0` 填补。历史涨停事件被修正后，后续首板、连板高度和连板率随读取自动更新。

### 4.3 Skill 获取或用户补充

- 每日涨停和跌停方向的完整事件快照
- 上涨家数、下跌家数、中位数涨跌幅、回头波数
- 上海 / 深圳 / 北京两融余额
- 上海 / 深圳 / 创业板 / 北京成交额
- 总市值、流通市值
- 上海 PE、深圳 PE、创业板 PE、全市场 PE
- 平均股价

Skill 可通过 API、网络查询、询问用户或其他可用方式取得这些数据。需要用户补数时，一次性给出带单位的 YAML 或表格模板，不逐项对话。用户可以暂时跳过；新记录中跳过的字段保存为空值，不得使用 `0` 或前一交易日数据代替。已有记录的跳过语义见第 7.5 节。

## 5. 总体复盘操作

### 5.1 写入复盘

用户可以请求：

> 生成今天的总体复盘。

或者：

> 生成 2026-08-21 的总体复盘。

用户可在任意日历日发起请求（包括周末和节假日）。正式记录的业务日期必须是已收盘交易日，见第 9 节。

Skill 可通过 API、网络查询、询问用户或其他可用方式取得数据。需要用户补充时，一次性列出本次尚未取得的内容；用户可以跳过任何字段。

用户要求写入时，Skill 将本次已经取得或由用户提供的数据调用 `packages/marketreview` 写入。不要求所有指标齐全，不保存采集状态，也不为未取得的字段猜测数值。字段级 patch 规则为：

- 未提供字段：保留原值；
- 具体值，包括 `0`：更新；
- 显式 `null`：清空；
- 新记录中未提供的原子字段：保持 `null`。

### 5.2 每日涨跌停事件写入

涨停和跌停按方向分别提交完整快照。正式数据库不保存部分名单：某方向存在 `daily_price_limit_snapshot` 记录，表示该交易日该方向名单已完整确认；不存在则表示未知，不能按零计算。完整快照可以是空列表，表示已确认当日该方向没有符合口径的触板股票。

示例：

```text
本次尚未取得以下数据（可跳过）：

- 上海两融余额（元）
- 北京两融余额（元）
```

用户提交后，package 校验数值和单位，再按第 7.5 节做字段级 patch。所有数量字段均为可空的非负整数：`null` 表示缺失，`0` 表示已经确认数量为零。最终展示遵循第 6 节：缺失值留空，已确认的 `0` 必须展示。

涨跌停事件的最小 YAML 输入示例：

```yaml
trade_date: 2026-08-21
price_limit_snapshots:
  - direction: up
    events:
      - market: sh
        code: "600519"
        name: 贵州茅台
        closed_at_limit: true
        limit_rate_bp: 1000
  - direction: down
    events: []
```

事件记录存在即表示盘中曾触及对应方向的涨跌停价。`direction=up, closed_at_limit=true` 表示有效涨停，`false` 表示涨停炸板；`direction=down, closed_at_limit=true` 表示收盘跌停，`false` 表示打开跌停。上述空的跌停快照表示当日已确认没有触及跌停的股票。

### 5.3 显示复盘

用户要求显示时，Skill 只读取数据库并格式化展示，不自动取数、不追问缺失数据、不判断复盘是否“完整”。数据库中没有该交易日的复盘记录时，显示“无复盘数据”；原子字段为 `null` 时，对应单元格留空。

读取复盘时计算第 4.2 节派生指标，再按类别展示。Skill 不单独实现这些公式。

涨跌停比使用“有效涨停数 : 收盘跌停数”的方向展示，不使用百分数。两边都大于 0 时，将较小的一边归一化为 1，倍数保留两位小数：

- 有效涨停 58 只、收盘跌停 15 只，显示 `3.87:1`
- 有效涨停 4 只、收盘跌停 15 只，显示 `1:3.75`
- 两边相等，显示 `1:1`
- 只有一边为 0 时保留真实数量，显示为 `12:0` 或 `0:12`
- 两边都为 0 时，两项数量分别显示 `0`，涨跌停比留空
- 任一基础数据缺失时，涨跌停比留空

### 5.4 保存与查看

同一个交易日只保存一份总体复盘。再次执行时按字段级 patch 更新，不创建重复记录。

用户可以请求查看已保存的历史总体复盘。查询走 `packages/marketreview`，从数据库读取原子字段并计算派生指标；查询本身不修改数据库。

## 6. 展示方式

总体复盘按类别使用简单表格展示：

| 指标 | 数值 |
| --- | --- |
| 有效涨停（只） | 52 |
| 炸板率 | 18.75% |
| 上海成交额（亿元） | 8,432.16 |

展示要求：

- 只展示指标和值；
- 单位写在指标名称或数值中；展示层将库内的元换算为亿元或万亿元，将小数形式的比率换算为百分数；
- 不展示采集方式或更新时间；
- 没有对应数据时单元格留空，不显示 `—`、`0` 或其他占位符；
- 已确认的数值为 0 时必须显示 `0`，不能按缺失数据处理；
- 某方向快照完整且事件为空时，对应基础数量按 `0` 展示；快照不存在时留空；
- 上一交易日涨停快照缺失时，首板、连板高度、最高板和各高度数量留空，不把未知历史当作首板；
- 不同类别分别展示。

## 7. 数据存储

### 7.1 数据库定位

Skill 和未来应用必须通过 `packages/marketreview` 读写数据库。

复盘数据复用现有 Stock Pilot runtime，默认路径：

```text
<workspace>/stockpilot/db/market_review.sqlite3
```

- Skill 安装目录不保存用户数据；
- 不新建 `~/.stockpilot/daily-market-review/` 第三套目录；
- 可通过现有 runtime 配置修改数据目录。
- 应用尚未上线，当前 schema 变更按新建数据库处理，不设计旧库迁移或兼容读取。

数据库只保存复盘原子指标、每日涨跌停完整性快照和触板事件，不保存数据来源、采集方式、网页证据、候选值、`streak_height` 或可由已存数据稳定计算的展示字段。Skill 负责通过 API、网络查询或询问用户取得数据，数据库不关心数据的取得方式。V2 / V3 不增加重复的日度聚合表。

### 7.2 单位

数据库统一使用标准单位：

| 类别 | 存储 | 展示 |
| --- | --- | --- |
| 成交额、市值、两融余额 | 元 | 亿元或万亿元 |
| 百分比类指标（中位数涨跌幅、炸板率、连板率、指数涨跌幅等） | 小数，例如 `0.1875` | 百分数，例如 `18.75%` |
| 指数点位、PE、平均股价 | 原单位数值 | 原单位，按附录保留小数位 |

两融按其业务交易日归属写入对应交易日，即使实际要到 T+1 才公布。不得拿前一日余额冒充当日数据。

### 7.3 核心数据表

| 数据表 | 用途 |
| --- | --- |
| `daily_market_review` | 每个交易日一条总体复盘；只保存原子指标 |
| `daily_price_limit_snapshot` | 一个交易日、一个方向一条完整性记录；`direction in (up, down)`，存在即表示该方向完整，缺失表示未知 |
| `daily_price_limit_event` | 一只股票在一个交易日触及一个方向的涨跌停价时一条记录，保存方向、收盘状态和涨跌幅限制 |

`daily_price_limit_event` 使用「交易日期 + 市场 + 6 位代码 + 方向」作为唯一键，允许极端情况下同一股票同日分别触及上下限。它通过「交易日期 + 方向」引用 `daily_price_limit_snapshot`；删除某方向快照时级联删除该方向事件。涨跌停事实独立于总体复盘存在，删除 `daily_market_review` 不删除同日涨跌停事件。

入库身份对齐 `packages/marketdata` 证券主数据已有的 `(market, code)` 模型：`market` 使用小写 `sh | sz | bj`，`code` 使用保留前导零的 6 位字符串。package 返回结果时可组合为 `<market>.<code>`，例如 `sh.600519`、`sz.000001`、`bj.830799`；展示时只显示 6 位代码。V1 写入 API 要求调用方明确提交 `market` 和 `code`，不依赖裸代码猜测市场。现有 `standardize_security_identity` 是只支持沪深的 T+0 合同，本功能不扩展或复制该合同。

事件表只接收已按第 10 节证券宇宙过滤的完整名单，不保存恒为 `false` 的 `is_st`。在接入历史证券状态前，package 不宣称能独立复核调用方的全部过滤结果。

`daily_market_review` 中的指数字段为各指数的当日收盘点位和前收盘点位，不保存涨跌点数和涨跌幅。两融和成交额只保存各市场原始值。有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板及全部连板汇总均不保存在该表中。

### 7.4 每日涨跌停事件

一条 `daily_price_limit_event` 的存在表示该股票当日盘中曾触及 `direction` 对应的涨跌停价：

| `direction` | `closed_at_limit` | 业务含义 |
| --- | --- | --- |
| `up` | `true` | 有效涨停，参与首板和连板计算 |
| `up` | `false` | 涨停炸板，不产生当日板数并中断连续性 |
| `down` | `true` | 收盘跌停 |
| `down` | `false` | 打开跌停 |

`limit_rate_bp` 使用整数基点保存当日适用限制，例如 10% 为 `1000`、20% 为 `2000`、30% 为 `3000`。事件表不保存 `touched_at_limit=true`，因为记录存在本身已经表达触板；也不保存 `streak_height`。

连板高度只对 `direction=up and closed_at_limit=true` 的事件计算。系统按交易日历逐日向前匹配完整涨停快照：上一交易日完整且没有该股票有效涨停时，今日为首板；上一交易日也有效涨停时继续累计；向前遇到缺失快照时高度为未知，不得按首板处理。

### 7.5 同日重跑：字段级 patch

同一交易日再次生成或补充时，不做整日覆盖：

| 本轮行为 | 结果 |
| --- | --- |
| 未提供某字段 | 保持原值 |
| 提供具体数值 | 更新，包括合法的 `0` |
| 显式提供 `null` | 清空该字段 |
| 新记录中跳过的字段 | 保存为空 |
| 某方向完整事件快照 | 事务性整体替换该日该方向事件；空列表表示已确认该方向零触板 |
| 某方向单股修订 | 只允许在该日该方向已有完整快照时新增、更新或删除事件 |

#### 涨跌停事件写入模式

| 模式 | 输入和结果 |
| --- | --- |
| `snapshot_replace` | 为 `trade_date + direction` 提交全量事件；验证通过后事务性整体替换，空列表表示确认零触板 |
| `item_patch` | 在已有完整快照上新增、更新或删除单只股票事件，不得隐式创建不完整快照 |

新增或更新必须提交 `market`、`code`、`name`、`closed_at_limit` 和 `limit_rate_bp`；删除只需 `market + code`。同一完整快照中方向固定，不允许事件携带不同方向。市场、代码、布尔值、涨跌幅限制或重复身份不合法时，必须拒绝整次请求，不得仅跳过问题股票。

同一次总体复盘 patch 中可同时包含原子指标、涨停快照和跌停快照，并使用同一数据库事务。任一方向事件校验失败时，本次提交的其他字段和方向也全部回滚。

事件校验错误必须是用户可见的结构化错误：

| 错误码 | 场景 | Skill 提示 |
| --- | --- | --- |
| `INVALID_FIELD_VALUE` | 方向、市场、代码、收盘状态、涨跌幅限制或其他输入不合法 | 说明本次请求未写入任何数据 |
| `DUPLICATE_PRICE_LIMIT_EVENT` | 同一快照存在重复的股票方向身份 | 列出重复身份并提示修正后重试 |
| `PRICE_LIMIT_SNAPSHOT_REQUIRED` | 在不存在完整快照的方向执行单股修订 | 提示先提交该方向完整快照 |

### 7.6 数据库读写能力

共享数据层必须提供：

- 新增或 patch 指定交易日的总体复盘原子字段；
- 查询单个交易日或日期范围（返回原子字段 + 读时计算的派生指标）；
- 删除指定交易日的总体复盘；涨跌停事件作为共享事实独立保留；
- 按方向整体替换完整事件快照，以及在已有完整快照上按股票增删改事件；
- 查询单日或日期范围内的原始涨跌停事件和快照完整性；
- 根据事件计算有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板和炸板率；
- 根据连续的完整涨停快照计算首板、连板数、最高板、最高板代表和各高度数量；缺失快照时返回未知而不是零。

## 8. 技术边界

- 指标合同、校验、字段级 patch、涨跌停事件快照、连板派生、读时计算和 SQLite 访问放在 `packages/marketreview/`；
- 行情和交易日历复用 `packages/marketdata/`；
- 数据获取和复盘生成流程由 `skills/daily-market-review/` 负责；
- `packages/marketreview` 不提供 `auto_patch_indices`、`fetch_index_atoms` 或 `IndexFetchResult` 之类的外部采集编排接口；
- 数据库使用 SQLite；
- 公共字段使用 `snake_case`。

## 9. 交易日与收盘约束

V1 只允许为已收盘交易日生成正式记录。用户可以在非交易日运行 Skill，但写入的 `trade_date` 必须是交易日。

- 未指定日期时，落到最近一个已收盘交易日；
- 用户显式指定非交易日：不落库，并提示最近交易日；
- 目标日为当日且尚未收盘：拒绝生成正式记录；
- 历史已收盘交易日可直接生成或补充；
- 暂以 A 股统一 15:00 作为日度复盘收盘边界。

当前 `packages/marketdata` 交易日历尚无独立北交所市场合同。V1 默认北交所与沪深交易日一致，统一使用沪深交易日判断 A 股复盘日期；若未来出现差异日期，V1 不允许单独为北交所开另一条当日记录，待后续扩展多市场日历合同。

## 10. 复盘证券宇宙与 ST 排除

V1 涨跌停与连板的证券宇宙为上海、深圳、北京交易所上市的人民币普通股票。排除 B 股、ETF、基金、债券、可转债、退市整理股票、上市首日及当日无涨跌幅限制的股票；同时排除 ST 股票。

具体口径：

- 排除交易日当日处于 `ST`、`*ST` 等特别处理状态的股票；
- 有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板均不统计 ST 股票；
- 昨日有效涨停分母和每日涨跌停事件也不统计 ST 股票；
- ST 股票不进入 `daily_price_limit_event`；
- 连板高度只计算连续的、符合复盘证券宇宙条件的非 ST 涨停交易日；
- 股票进入 ST 状态时原连板连续性终止；以后撤销 ST 后再次涨停，应重新从一板起算；
- ST 判断以对应交易日的历史状态为准，不能使用股票当前名称或当前 ST 状态回填历史数据；
- 内部建议使用按交易日生效的 `is_st` 或证券状态字段，不依赖临时的名称字符串判断。

因此，所有涨跌停派生指标也自然排除 ST：

- 炸板率的分子和分母均不含 ST；
- 涨跌停比两侧均不含 ST；
- 连板率的分子与上一交易日有效涨停分母均不含 ST。

市场宽度、成交额、市值、PE 等直接录入或全市场口径的指标，仍以证券软件展示为准，不在本条强制重算；调用方提交每日涨跌停事件快照时，必须先按上述证券宇宙口径过滤。

### 10.1 涨跌停细分口径

- `20% 涨停` 统计创业板和科创板中适用 20% 涨跌幅限制且收盘涨停的非 ST 股票。
- 北交所适用 30% 涨跌幅限制的非 ST 股票，计入有效涨停、打开跌停、收盘跌停和涨停炸板等相应基础数量，但不计入 `20% 涨停`；V1 不另设 `30% 涨停` 展示项。
- 当日盘中打开后重新封住涨停且收盘仍为涨停，计入有效涨停，不计入涨停炸板。
- 当日曾触及涨停但收盘未封住，计入涨停炸板。

### 10.2 连板连续性

- 首板和所有连板都来自每日有效涨停事件；数据库不直接记录板数。
- 每一个连续交易日都必须属于上述证券宇宙并收盘涨停；停牌、收盘未涨停、进入 ST、进入退市整理期或出现无涨跌幅限制交易日，均中断连板。
- 炸板后回封并以涨停收盘，仍视为当日涨停，连板可以延续；收盘未封住则中断。
- 连板率固定使用「今日二板及以上非 ST 股票数 ÷ 上一交易日非 ST 有效涨停数」。
- 上一交易日涨停快照完整且没有该股票有效涨停时，才能确认今日为首板；向前遇到缺失快照时，相关高度和依赖完整高度的聚合留空。

### 10.3 V1 事件快照的责任

V1 保存全部符合口径的触及涨停或跌停股票。涨停和跌停方向分别形成完整快照；没有快照表示未知，完整空快照才表示零。数据提供方对名单已按本节证券宇宙过滤负责，系统负责身份、方向、收盘状态、涨跌幅限制、重复记录和完整快照写入语义。

有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板和连板汇总不再接受独立手工聚合值，统一从事件计算，从数据结构上消除聚合值与个股名单不一致的问题。

在接入按交易日生效的证券状态合同前，`packages/marketreview` 不根据当前股票名称推断历史 ST 状态，也不声称能够独立复核调用方的历史证券宇宙过滤结果。

## 11. V1 验收标准

1. 用户未指定日期且在非交易日或盘前发起时，使用最近一个已收盘交易日；用户显式指定非交易日时不落库并提示最近交易日；用户显式指定尚未收盘的当日时拒绝生成正式记录。
2. 自动获取仅承诺三只指数的日 K；成功则写入收盘与前收盘，失败不覆盖原值、不用其他日期顶替。
3. 用户要求写入时，Skill 只写入本次取得或由用户提供的数据；复盘原子字段允许缺失，涨停和跌停事件只在对应方向完整时提交快照。
4. 涨跌停基础数量、炸板率、涨跌停比、首板与连板汇总、连板率、两融合计、成交额合计、指数涨跌点数和涨跌幅均在读取时计算，不入库。
5. 数据库只保存原子字段；同一交易日重复执行不产生重复记录，并遵守字段级 patch。
6. 用户要求显示时，Skill 只读取和格式化已保存的复盘，不自动取数、追问或修改数据库；原子字段为 `null` 时留空。
7. 总体复盘按照八个类别以简单表格展示，表格只显示指标和值。
8. 默认数据库路径为 `<workspace>/stockpilot/db/market_review.sqlite3`。
9. 数据层支持总体复盘的新增、查询、patch 和删除，支持按单日和日期范围查询，可被 Skill 之外的应用调用。
10. 涨停和跌停分别具有完整快照；无快照表示未知，完整空快照表示对应数量为 `0`。
11. `daily_price_limit_event` 使用日期、市场、代码和方向作为唯一键；删除方向快照级联删除该方向事件，删除总体复盘不删除事件事实。
12. 数据库不保存数据来源或采集方式。
13. `2026-08-21` 已由仓库沪深交易日历确认为已收盘交易日，前一交易日固定为 `2026-08-20`。黄金 fixture 至少包括连续多个交易日的涨停完整快照、当日跌停完整快照、首板、连板、涨停炸板、打开跌停和收盘跌停事件，以及所有派生指标预期结果。
14. 验收覆盖涨停完整但跌停缺失、跌停完整但涨停缺失、完整空快照、历史涨停快照缺失导致高度未知，以及同一股票不同方向身份的语义。
15. 事件写入验收覆盖按方向全量替换、已有完整快照上的单股增删改、无完整快照时拒绝单股修订，以及任一非法事件导致整次事务回滚。

## 12. 暂缓范围

- 午间数据、开盘数据和情绪周期阶段判断不在 V1。
- 涨跌停事件、市场宽度、两融、市场成交额、市值、PE 和平均股价的专用自动采集 provider 不在 V1；Skill 仍可通过可用来源取得完整快照后提交。
